# HTTP 协议基础

HTTP（HyperText Transfer Protocol，超文本传输协议）是万维网的数据通信基础。它是一个客户端-服务器协议，客户端发起请求，服务器返回响应。

## 请求-响应模型

HTTP 工作在 TCP/IP 协议之上，默认端口是 80（HTTP）和 443（HTTPS）。客户端发送一个 HTTP 请求，服务器处理后返回一个 HTTP 响应。这个过程是无状态的，也就是说服务器不会保存两次请求之间的任何信息。

无状态意味着每个请求都是独立的，服务器不记得之前的交互。为了实现状态管理，人们发明了 Cookie 和 Session 机制。Cookie 是服务器发送到浏览器并保存在本地的一小块数据，浏览器下次请求时会自动带上它。

## HTTP 方法

HTTP 定义了一组请求方法，用来表示对资源的操作类型。最常用的有 GET、POST、PUT、DELETE 这四个。

GET 方法用于请求获取资源。它是安全的，也就是说不应该改变服务器上的资源状态。GET 请求的参数通常附在 URL 后面，用问号分隔，比如 `example.com/search?q=hello`。因为参数在 URL 里，所以长度有限制，而且会暴露在地址栏中，不适合传敏感信息。

POST 方法用于提交数据，比如提交表单、上传文件。它不是安全的，可能会改变服务器上的资源。POST 的数据放在请求体里，不会显示在 URL 中，理论上没有长度限制。

PUT 方法用于更新资源，或者在资源不存在时创建它。PUT 是幂等的，也就是说多次调用同一个 PUT 请求的效果和调用一次是一样的。这和 POST 不同，POST 多次调用可能会产生不同的结果（比如多次提交订单会创建多个订单）。

DELETE 方法用于删除指定的资源。和 PUT 一样，DELETE 也是幂等的。

## 状态码

HTTP 响应的第一行包含状态码，用三位数字表示请求的结果。状态码分为五类：

- 1xx：信息性状态码，表示请求已接收，继续处理
- 2xx：成功状态码，表示请求已成功处理。最常见的是 200 OK
- 3xx：重定向状态码，表示需要进一步操作才能完成请求。比如 301 永久重定向、302 临时重定向
- 4xx：客户端错误状态码，表示请求有问题。比如 404 Not Found（资源不存在）、403 Forbidden（没有权限）
- 5xx：服务器错误状态码，表示服务器处理请求时出错了。比如 500 Internal Server Error

301 和 302 的区别很重要。301 是永久重定向，搜索引擎会把旧地址的权重转移到新地址。302 是临时重定向，搜索引擎不会转移权重。所以如果你的网站域名换了，应该用 301 重定向。

## HTTP 头部

HTTP 请求和响应都包含头部（Headers），用来传递附加信息。头部是键值对的形式，每行一个。

常见的请求头有：
- User-Agent：浏览器的身份标识
- Accept：客户端能接受的内容类型
- Content-Type：请求体的媒体类型
- Cookie：客户端保存的 Cookie

常见的响应头有：
- Content-Type：响应体的媒体类型
- Set-Cookie：设置 Cookie
- Cache-Control：缓存控制策略
- Location：重定向的目标地址

## HTTPS

HTTPS 是 HTTP 的安全版本，它在 HTTP 和 TCP 之间加了一层 TLS/SSL 加密层。所有数据在传输过程中都是加密的，第三方无法窃听或篡改。

HTTPS 使用非对称加密来交换密钥，然后用对称加密来传输数据。非对称加密慢但安全，适合交换密钥；对称加密快，适合大量数据传输。

HTTPS 不仅加密数据，还能验证服务器身份，防止中间人攻击。现在主流网站都使用 HTTPS，浏览器也会标记 HTTP 网站为"不安全"。
