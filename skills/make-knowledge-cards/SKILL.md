# Make Knowledge Cards

## Overview

将长文本提炼为一组结构化知识卡片，每张卡片聚焦一个独立知识点，便于快速学习和间隔复习。

## Input Sources

支持两种输入方式，按以下优先级处理：

1. **用户直接粘贴的文本** — 对话中提供的文章、笔记或段落
2. **本地文件** — 用户指定路径的 `.md` 或 `.txt` 文件，用 `Read` 工具读取全文

**不支持的输入（明确告知用户）：**
- 网页 URL（不做网页抓取）
- PDF 文件
- Anki 卡片包
- 图片 / 截图（不做 OCR）

## Knowledge Extraction Principles

提取知识时严格遵循以下原则：

1. **只提取真正重要的知识** — 跳过铺垫、过渡、客套话、重复论述，抓住核心概念、关键结论、重要方法
2. **一张卡片一个知识点** — 每张卡片只讲一个独立的概念、原理、方法或事实，不混杂多个主题
3. **删除重复内容** — 同一知识点在原文中反复出现时，只保留最清晰、最完整的表述
4. **绝不编造** — 卡片中的所有信息必须能在原文中找到依据，不得添加原文没有的定义、例子或推论
5. **不强行凑数量** — 如果原文信息量不足，宁可少做几张卡片，也不要把不重要的内容硬塞进来。卡片数量范围是 **5～8 张**，下限 5 张，上限 8 张

## Card Structure

每张卡片包含以下四个字段，顺序固定：

### 1. 标题
- 用短语概括该卡片的核心知识点
- 简洁明确，不超过 20 字
- 示例：`梯度下降的基本思想`、`HTTP 状态码 301 vs 302`

### 2. 核心知识
- 用 1～2 句话提炼该知识点的核心内容
- 是对原文的精准概括，不是照抄
- 读者读完这一段就能抓住要点

### 3. 简明解释
- 对核心知识做进一步展开说明
- 解释原理、机制、适用条件、注意事项等
- 控制在 3～5 句话，保持精炼

### 4. 例子或自测问题
- **优先用例子**：如果原文中有具体例子、案例、应用场景，提炼后放在这里
- **没有例子时用自测问题**：设计一个能检验是否理解该知识点的问题
- 自测问题应以问答形式呈现，例如：`问：什么情况下应该用栈而不是队列？`
- 例子和自测问题二选一，不要同时出现

## Output Format

用 Markdown 输出，每张卡片用二级标题分隔，卡片内部用三级标题组织四个字段。

**输出模板：**

```markdown
## 卡片 1：[标题]

### 核心知识
[1～2 句话概括]

### 简明解释
[3～5 句话展开说明]

### 例子
[具体例子，或自测问题]
```

在所有卡片之前，加一行总览说明：

```
已从原文中提炼出 N 张知识卡片：
```

## Workflow

执行以下步骤：

1. **读取输入** — 获取全文内容（直接粘贴的文本或读取本地文件）
2. **通读与分段** — 快速通读全文，识别出主要知识点，初步划分主题
3. **筛选与去重** — 按重要性筛选，去掉重复和次要内容，保留 5～8 个核心知识点
4. **逐张制作卡片** — 为每个知识点填写四个字段，确保信息全部来自原文
5. **质量检查** — 对照五条提取原则检查每张卡片，必要时调整
6. **输出结果** — 按规定格式输出所有卡片

## Quality Checklist

输出前逐项确认：

- [ ] 卡片数量在 5～8 张之间
- [ ] 每张卡片只讲一个知识点
- [ ] 所有信息都能在原文中找到依据，没有编造
- [ ] 没有重复的知识点
- [ ] 每张卡片都包含完整的四个字段（标题、核心知识、简明解释、例子/自测问题）
- [ ] 语言精炼，没有冗余
